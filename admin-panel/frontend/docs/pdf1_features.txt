 Admin Dashboard & College Dashboard
 Product Features Documentation
 Feature-focused documentation describing the user-facing capabilities of both web
 dashboards.
Document Scope
This document focuses on what the application provides to administrators and college staff. It intentionally avoids
technical architecture, database design, APIs, infrastructure, and implementation details.
Product principle
The Admin Dashboard provides centralized company-wide control, while the College Dashboard provides a
simple, college-scoped workspace for managing approved students and services.

1. Product Overview
BEXO Web Application is organized around two primary web experiences: the Admin Dashboard for
company-level control and the College Dashboard for approved college staff.
The two dashboards serve different responsibilities but operate as parts of the same platform. The Admin
Dashboard manages the overall ecosystem of colleges, users, agreements, access, services, students,
provisioning, notifications and operational oversight. The College Dashboard allows authorized college staff to
perform day-to-day student and college operations within their permitted scope.
2. Admin Dashboard — Company Control Center
Purpose
The Admin Dashboard is the central control center for the company. It gives authorized company administrators
visibility and control over colleges, agreements, services, quotas, users, students, access, provisioning activity,
notifications and important operational events.

3. College Dashboard — College Operations Workspace
Purpose
The College Dashboard is the college-facing web workspace for authorized college staff. Its primary purpose is to
make student access and college operations simple, clear and low-effort while keeping the college inside the
access and service scope approved by BEXO.
The experience is designed around a simple operational journey: Login → Give Student Access → Select
Range or Upload → Review → Confirm & Grant.
3.1 College Home Dashboard
  Shows the college's current operating status.
  Displays student quota used and remaining.
  Provides a primary action to give students access.
  Shows recent provisioning batches.
  Shows students successfully activated or processed.
  Highlights quota warnings and failed records that require attention.
 
3.2 Student Management
  View students belonging to the college.
  Search and review student information.
  View student status and access status.
  Review roll/enrollment number, name, email and department where available.
  Review student access or entitlement information.
  Support individual student-level operational actions when permitted.
 
3.3 Give Student Access
  Provides the main workflow for granting eligible students access to a service.
  Allows staff to choose a roll-number range or upload student information.
  Provides a review stage before access is granted.
  Shows the number of records being processed and any validation issues.
  Allows staff to confirm and grant access after reviewing the information.
 
3.4 Roll-Number Range Provisioning
  Allows college staff to provide a range of student roll/enrollment numbers.
  Validates the selected range before processing.
  Helps staff grant access to a group of students without manually entering every record.
  Uses the college's available quota and approved service scope.
 
3.5 Student File Import
  Allows student data to be provided through supported file formats such as CSV and XLSX.
  PDF import may be supported where the document can be reliably interpreted.
  Validates required student information before processing.

7. Product Experience Principles
  The Admin Dashboard is designed for control, visibility, governance and operational management.
  The College Dashboard is designed for simplicity, minimum clicks and day-to-day execution.
  College staff should not need technical knowledge to provision students.
  Important actions should provide clear status, confirmation and error information.
  Company-level controls remain authoritative over college-level operations.
  College users see only information and actions applicable to their approved college scope.
  Student access is treated as a controlled entitlement rather than a permanent unrestricted flag.
  Suspension should affect access while preserving student records and operational history.
  Large student operations should be easy to start and easy to monitor.
  Notifications should keep administrators and college staff informed of actions requiring attention.
 
8. Feature Summary
The BEXO web application therefore consists of two complementary dashboards. The Admin Dashboard is the
command center for the entire college ecosystem, giving the company control over colleges, agreements, quotas,
access, users, students, services, provisioning, notifications, reporting and security. The College Dashboard is
the operational workspace for each approved college, focused on student management, access provisioning,
service visibility, requests, notifications, reporting and college-specific administration.
Together, these dashboards provide a clear separation of responsibilities: BEXO controls the platform centrally,
while colleges operate their approved student workflows within the scope granted to them.
Document note: This feature documentation is based on the existing Company College Portal product documentation and the
