## 3. Service-to-Service Authentication Protocol

### Service Token Architecture
Communication between microservices uses cryptographically signed JWT service tokens generated by `src/integrations/serviceAuth.ts`.

#### Token Claims Specification
- `iss`: `"bexo-admin-panel"` (Issuer)
- `aud`: Target service audience (`"bexo-college-panel"` or `"bexo-mobile-backend"`)
- `sub`: `"admin-service-actor"`
- `scope`: Permitted service scope (e.g., `"college:lifecycle:sync"`, `"student:entitlement:sync"`)
- `iat`: Epoch timestamp of issuance
- `exp`: Short-lived expiration (default: 5 minutes / 300 seconds)

### Mutual Transport Headers
All inter-service HTTP requests require three mandatory headers:
```http
X-Service-Token: <signed_service_jwt>
X-Correlation-ID: <uuidv4_trace_identifier>
X-Bexo-Service: admin-panel
```

## 4. Cross-System Event Payloads & Synchronization Contracts

### 4.1 College Lifecycle Synchronization
- **Trigger**: College onboarding, metadata modification, suspension, reactivation, or quota changes.
- **Direction**: Central Admin Backend -> College Panel (`POST /api/internal/colleges/lifecycle-sync`)
- **Payload Schema**:
  ```json
  {
    "event": "college.status_updated",
    "collegeId": "clg-psg-01",
    "status": "Suspended",
    "quotaAllocated": 1500,
    "enabledServices": ["campus_ai", "resume_builder", "mock_interviews"],
    "timestamp": "2026-10-15T12:00:00.000Z",
    "correlationId": "abf9d69b-4f38-4dfc-b992-2c65a48ce7b2"
  }
  ```
- **College Panel Reaction**:
  - `Suspended`: Invalidate active faculty/student sessions, lock student app authentication.
  - `Active`: Re-enable access, update local quotas.

### 4.2 Student Entitlement Synchronization
- **Trigger**: Batch provisioning run, manual student enrollment, or access revocation.
- **Direction**: Central Admin Backend -> BEXO Mobile Backend (`POST /api/internal/students/entitlement-sync`)
- **Payload Schema**:
  ```json
  {
    "event": "student.entitlement_updated",
    "studentId": "stu-psg-001",
    "collegeId": "clg-psg-01",
    "rollNumber": "24CS001",
    "email": "student001@psgtech.ac.in",
    "status": "Active",
    "modules": ["campus_ai", "resume_builder", "learning_paths"],
    "timestamp": "2026-10-15T12:00:00.000Z",
    "correlationId": "e8f5ac7f-4af0-462c-9f74-7f378f18e525"
  }
  ```
- **Mobile Backend Reaction**:
  - Immediately grants or revokes mobile feature flags.
  - Invalidates student mobile refresh tokens if status is `Suspended`.

## 5. Resiliency, Timeouts & Error Degradation

### Non-Blocking Asynchronous Dispatch
Inter-service synchronization is non-blocking. A temporary network outage in a downstream consumer (e.g. mobile backend downtime) will not fail the primary admin panel transaction.

### Retry Strategy with Exponential Backoff
Implemented in `CollegePanelClient` (`src/integrations/collegePanelClient.ts`):
1. **Attempt 1**: Immediate call with 5,000ms timeout.
2. **Attempt 2**: Wait 300ms + jitter before retry.
3. **Attempt 3**: Wait 600ms + jitter before retry.
4. **Failure**: Logs structured critical alert with `correlationId` to dead-letter queue / audit log.

## 6. Future Integration Playbook

When ready to wire the three codebases together in production, follow this step-by-step checklist:

### Step 1: Shared Secret & Environment Configuration
1. Configure `JWT_SECRET` across all services to use a shared asymmetric key pair (RS256 / Ed25519) or shared HMAC secret.
2. In `college-panel/backend/.env`:
   - Set `ADMIN_PANEL_URL=http://localhost:8080`
   - Set `SERVICE_AUTH_SECRET=<jwt_secret>`
3. In `Bexo_mobile_App-main/backend/.env`:
   - Set `ADMIN_PANEL_URL=http://localhost:8080`
   - Set `SERVICE_AUTH_SECRET=<jwt_secret>`

### Step 2: Implement Internal Receiver Endpoints in Downstream Services
In `college-panel/backend/src/routes/internalRoutes.ts`:
```typescript
import { Router } from 'express';
import { verifyServiceToken } from '../middlewares/serviceAuth';

const router = Router();
router.post('/colleges/lifecycle-sync', verifyServiceToken('bexo-college-panel'), (req, res) => {
  const { event, collegeId, status, quotaAllocated } = req.body;
  // Update local college cache or notify active sessions
  res.json({ success: true, processed: true });
});
export default router;
```

In `Bexo_mobile_App-main/backend/routes/internalRoutes.js`:
```javascript
router.post('/students/entitlement-sync', verifyServiceToken('bexo-mobile-backend'), async (req, res) => {
  const { studentId, status, modules } = req.body;
  // Update student permissions in mobile DB
  res.json({ success: true, acknowledged: true });
});
```

### Step 3: Zero-Rewrite Architectural Verification
Because the Admin Backend already contains `src/integrations/collegePanelClient.ts`, `src/integrations/mobileAppClient.ts`, and `src/integrations/serviceAuth.ts`:
- No database migrations are required in the Admin Backend.
- No modifications to the Admin Panel frontend UI or API contracts are needed.
- Multi-tenant perimeter rules remain 100% intact.
